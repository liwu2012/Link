# 金蝶云星空 8.2 批次追溯（正查 / 反查）操作说明

> 适用范围：K3Cloud 8.2，启用批号管理，有联副产品、半成品、原料，生产入库与生产领料批号必填。
> 本说明分两部分：**部署（一次性）** 和 **日常操作**。部署完成后，业务人员只看第四章。

---

## 一、这套东西能做什么

| 能力 | 说明 |
|---|---|
| 正查 | 输入成品批号，查到它用了哪些原料批号、对应哪些生产订单 |
| 反查 | 输入原料批号，查到它流向了哪些成品/半成品批号（含主产品、联产品、副产品） |
| 按工单查 | 输入生产订单号，同时看到该单全部投入批号和全部产出批号 |
| 多层级 | 原料 → 半成品 → 成品，逐层展开，默认 6 层，最多 20 层 |
| 图谱展示 | 网页版血缘图，点击节点高亮上游/下游，支持“只看血缘” |
| 统计报表 | 每个批号的领用量、产出量、上下游批号数、关联工单数 |

原理：单据审核时把“批号 → 工单 → 批号”的对应关系写入一张关系表 `ZYKJ_LOT_TRACE_EDGE`，查询时在这张表上做广度优先遍历。**不改动金蝶标准表结构**。

## 三、部署（一次性）

### 3.1 环境准备

- 有 BOS 二开权限，能注册插件、建动态表单
- 能访问数据库（执行建表与回填脚本）
- Visual Studio，引用网站 `Bin` 目录下的金蝶 DLL

### 3.2 执行建表

在数据中心库执行 `sql/01_create_edge_table.sql`，确认表 `ZYKJ_LOT_TRACE_EDGE` 和两个索引已创建。

### 3.3 核对字段标识（必做）

打开 `src/TraceSchema.cs`，把标 `TODO` 的项按你环境的元数据改掉：

| 配置项 | 含义 |
|---|---|
| `InStockEntryKey` | 生产入库单分录实体标识 |
| `InStockLotKey` / `InStockMoEntryKey` | 入库分录的批号、源工单分录字段 |
| `InStockProductTypeKey` | 入库分录的产出类型（主产品/联产品/副产品） |
| `PickEntryKey` / `PickLotKey` / `PickMoEntryKey` | 领料单分录、批号、源工单分录字段 |
| `LotIdCol` / `LotNoCol` | 批号主档内码列、批号文本列 |

核对方法：BOS 设计器看字段标识，或数据字典查表结构。**这一步不做，插件拿不到数据。**

### 3.4 编译部署

1. `KingdeeTrace.csproj` 里把 `K3CloudBin` 指到你环境的 `WebSite\Bin`
2. 编译
3. 把 `KingdeeTrace.dll` 复制到 `WebSite\Bin`
4. 执行 `iisreset`

### 3.5 注册写关系插件（2 次）—— 二选一

**方式 A（推荐，Python 插件，免编译）**：用 [python/ZYKJ_TraceEdgeOp.py](python/ZYKJ_TraceEdgeOp.py)

在 BOS 设计器（每张单据各一次）：

1. 打开 **生产入库单** → 编辑 → **操作管理 → 审核（Audit）→ 服务端服务插件** → 新增，类型选 **Python 插件**，脚本文件名填 `ZYKJ_TraceEdgeOp`，绑定事件 `OnPreparePropertys` + `AfterExecuteOperationTransaction`
2. 打开 **生产领料单**，重复一次，同一个文件

**方式 B（C# DLL）**：部署 DLL 后，同样在 **审核 → 服务端服务插件** 新增，类名 `KingdeeTrace.PlugIns.TraceEdgeBillPlugIn,KingdeeTrace`

> 两种方式**只选一种**，否则审核一次会写两遍逻辑（虽有幂等兜底，但没必要）。
> Python 版改字段标识只需改文件顶部的 `RULES`，保存即生效，不用重编译。

为什么是两次：BOS 插件注册在单据元数据上，没有全局插件。以后加采购入库、销售出库等单据，也只需注册同一个类/文件，不用改代码。

### 3.6 建追溯查询动态表单

新建动态表单，标识建议 `ZYKJ_TRACE_QUERY`。

**单据头字段**

| 标识 | 类型 | 说明 |
|---|---|---|
| `FQueryMode` | 下拉 | `1` 按批号，`2` 按生产订单号，默认 1 |
| `FLot` | 基础资料（批号） | 按批号查询时使用 |
| `FMoBillNo` | 文本 | 按订单号查询，需完整订单号 |
| `FDirection` | 下拉 | `1` 正查，`2` 反查，默认 1 |
| `FDepth` | 整数 | 默认 6，范围 1～20 |
| `F_BTN_QUERY` | 按钮 | 标识必须一致 |

**单据体**：标识 `FEntity`，字段按下表建：

`FLevel`、`FNodeType`、`FNodeNo`、`FMaterialNo`、`FBillType`、`FBillNo`、`FQty`、`FProductType`、`FCreateTime`

另加一列 `F_URL`，字段类型选 **超链接**（打开方式=新窗口），标签“血缘图”。插件会自动给批号/工单行填深链，点开即进入 `KingdeeTrace/trace-lineage.html` 并自动查询。

**注册插件**：动态表单 → 插件 → 类名 `KingdeeTrace.PlugIns.TraceQueryPlugIn`

### 3.7 建统计报表动态表单

新建动态表单，标识建议 `ZYKJ_TRACE_STAT`。

- 单据头：`FBeginDate`（日期）、`FEndDate`（日期）、`FKeyword`（文本，批号或物料编码）
- 按钮：`F_BTN_STAT_QUERY`
- 单据体 `FEntity`：`FLotNo`、`FMaterialNo`、`FConsumedQty`、`FProducedQty`、`FUpLotCount`、`FDownLotCount`、`FMoCount`、`FFirstDate`、`FLastDate`
- 注册插件：`KingdeeTrace.PlugIns.TraceStatPlugIn`
- 先执行 `sql/03_report_views.sql`

### 3.8 部署图谱页面

1. 把 `web/trace-lineage.html` 放到 `WebSite\KingdeeTrace\`
2. 在 BOS 菜单挂“批次血缘图”，指向该页面
3. 页面与 K3Cloud 同站点，避免跨域

### 3.9 回填历史数据

执行 `sql/02_backfill_edges.sql`，顺序：采购入库 → 领料 → 生产入库 → 销售出库。脚本带 `NOT EXISTS`，可重复执行。

建议先跑一个月的数据，核对无误再全量。

### 3.10 接真实数据（可选）

页面默认用演示数据。切真实数据：

1. 编译部署 `TraceApiService`
2. 打开页面，把 `API_CONFIG.enabled` 改为 `true`
3. `API_CONFIG.url` 填 WebAPI 测试页显示的实际地址

接口用 **POST**，请求体：

```json
{ "parameters": [{ "type":"LOT", "no":"CP-01", "direction":0, "depth":6 }] }
```

`direction`：0 双向，1 正查，2 反查。

**前提**：自定义 WebAPI 需要上下文，调用前必须有有效的 WebAPI 登录会话，否则返回未登录。

## 四、日常操作

### 4.1 表单版追溯查询

1. 打开“批次追溯查询”
2. 选查询方式：
   - **按批号**：选择批号，选方向（正查 / 反查），点查询
   - **按生产订单号**：输入完整订单号，点查询（自动同时展开投入和产出）
3. 结果按层级排列：
   - `0` 层是起点
   - 数字递增表示离起点越远
   - “批号”和“工单”两种节点交替出现
   - 联副产品在“产出类型”列标注
4. 结果超过 5000 个节点会提示截断，缩小层级再查

### 4.2 图谱版（网页）

1. 输入批号或工单号，点“定位”
2. 点击任意节点：
   - 青色 = 上游（谁供给了它）
   - 琥珀色 = 下游（它流向了谁）
3. 点“只看血缘”：只保留这条链，隐藏无关节点
4. 点“显示全图”：还原
5. “单据视图”看单据，切“批号视图”更紧凑
6. 可切换深浅主题

### 4.3 统计报表

1. 选业务日期范围，可加批号/物料关键字
2. 点查询
3. 看每个批号的领用量、产出量、上下游批号数、关联工单数
4. 单次最多 2000 条，超出请缩小范围

## 五、运维

### 5.1 数据体检

| 视图 | 用途 |
|---|---|
| `V_ZYKJ_TRACE_COVERAGE` | 按月看“有上游投料的产出比例”，判断追溯完整度 |
| `V_ZYKJ_TRACE_BROKEN` | 列出“已入库但工单没有任何投料记录”的断链 |

建议每月跑一次，覆盖率明显偏低的月份通常是领料未录批号或历史没回填。

### 5.2 日志

插件异常写入 `TraceLog`（当前输出到 `Trace.WriteLine`，生产环境建议接入 BOS 日志或 log4net）。

### 5.3 补数

单据审核时写关系失败不会阻断审核，只记日志。发现缺边时：

1. 用 `V_ZYKJ_TRACE_BROKEN` 定位
2. 重跑 `02_backfill_edges.sql` 对应段落

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 查不到任何关系 | 领料单未录批号，或历史未回填 | 查断链视图，补录/回填 |
| 成品能查到工单，但工单下没有原料 | 领料边缺失 | 检查 `PickMoEntryKey` 字段标识是否正确 |
| 反向查一个原料带出几十个批号 | 联副产品共享投料，属正常 | 按工单分组看，不要按批号平铺 |
| 半成品批号查不到上下游 | 半成品未入库、无批号节点 | 半成品走生产入库并启用批号管理，或接受断链 |
| 接口返回未登录 | 自定义 WebAPI 无会话 | 先建立 WebAPI 登录态 |
| 页面请求被浏览器拦截 | 页面与 K3Cloud 不同源 | 部署到同一站点下 |
| 结果被截断 | 超过 5000 节点 | 降低层级或按工单分段查 |
| 审核后边表没数据 | 字段标识不对或插件没注册 | 看日志，核对 `TraceSchema` 与插件注册 |

## 七、上线验收清单

- [ ] 关系表与索引已建
- [ ] `TraceSchema` 中所有 TODO 已按环境核对
- [ ] DLL 已部署，IIS 已重启
- [ ] 生产入库单、生产领料单均已注册 `TraceEdgeBillPlugIn`
- [ ] 两张动态表单字段标识与说明一致，插件已注册
- [ ] 一张新生产入库单审核后，边表出现主产品与联副产品记录
- [ ] 一张新领料单审核后，边表出现原料批号到工单的记录
- [ ] 同一单据审核两次，边表条数不变
- [ ] 成品批号正查能到原料批号
- [ ] 原料批号反查能到主产品/联产品/副产品批号
- [ ] 半成品批号上下各跨一层
- [ ] 历史回填后，随机抽一个月手工核对一致
- [ ] 统计报表能出数，日期与关键字筛选正常
- [ ] 图谱页面在 K3Cloud 站点内可打开并定位

## 八、建议的上线节奏

1. 先只做**生产入库 + 生产领料**两条边，跑通“成品 ⇄ 原料”
2. 再用断链视图补齐历史
3. 然后加采购入库、销售出库、退料、调拨
4. 最后开放图谱页面与统计报表给业务使用
